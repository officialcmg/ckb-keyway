## Provider

```tsx
<KeyWayProvider appId="keyway_..." appName="Your app" theme="light" nodeMode="managed">
  <App />
</KeyWayProvider>
```

| Prop | Default | Purpose |
| --- | --- | --- |
| `appId` | none | Public application ID. Requests require a registered origin. |
| `appName` | `CKB KeyWay` | Modal branding, not the email sender or subject. |
| `theme` | `light` | Light or dark login/funding modals. |
| `nodeMode` | `managed` | Managed native hosting or optional browser WASM. |
| `autoConnect` | `false` | Opt into Fiber connection after login. Account recovery is always automatic. |
| `confirmFunding` | built-in modal | Optional approval callback for validated channel funding. |
| `onError` | none | Recovery, connection, and lease errors. |
| `onLifecycle` | none | Structured connection stages and elapsed timings. |

## Authentication: `useKeyWay()`

```ts
const { ready, authenticated, user, login, logout } = useKeyWay();
```

`ready` means session validation finished, not that the account or Fiber is ready. `user` contains the stable user ID. `login()` opens the OTP modal. `logout()` revokes the session; connected browser mode first performs its safe database backup. Managed nodes remain online.

## Account: `useCkbWallet()`

```ts
const { status, wallet, address, balance, refreshing, refreshBalance, error } = useCkbWallet();
```

`status` is `disconnected`, `recovering`, `ready`, or `error`. `wallet` contains public identity metadata. `balance` is a bigint in shannons, undefined until the independent on-chain read completes. `refreshBalance()` updates it without Fiber. A balance error does not invalidate the recovered account.

Arbitrary CKB signing is not exposed by this hook. The remote signer currently authorizes channel funding under backend policy.

## Fiber: `useFiber()`

```ts
const {
  status, nodeMode, connect, disconnect, channels, refreshChannels,
  openChannel, closeChannel, createInvoice, getInvoice, parseInvoice,
  preflightPayment, payInvoice, error, connection,
} = useFiber();
```

| Member | Behavior |
| --- | --- |
| `status` | disconnected, connecting, connected, or error. Connected does not imply a funded channel. |
| `connect()` | Start browser Fiber or attach to/provision managed Fiber. Does not fund a channel. |
| `disconnect()` | Disconnect the client; only browser mode stops the node. Does not settle channels. |
| `channels` | Normalized channels refreshed every ten seconds while connected. |
| `refreshChannels()` | Read channels and update React state. |
| `openChannel(options, onProgress?)` | Confirm/fund, wait for readiness, and refresh channels. |
| `closeChannel(id, options?)` | Request closure and refresh. On-chain settlement is asynchronous. |
| `createInvoice(params)` | Create a Fiber testnet invoice. |
| `getInvoice(params)` / `parseInvoice(params)` | Read invoice status or decode contents. |
| `preflightPayment(params)` | Test routing for an invoice/fee limit at that moment. |
| `payInvoice(invoice, options?)` | Submit, wait for successful settlement, and refresh. Show confirmation before calling. |
| `error` | Connection or channel-listing error. Mutation promises also reject and must be caught. |
| `connection` | Low-level escape hatch. Browser and managed method surfaces differ. |

`KeyWayLoginButton` provides login/logout; `KeyWayConnectButton` provides explicit Fiber connection. Headless connection factories and their types remain exported. No backend implementation or credentials are shipped.
